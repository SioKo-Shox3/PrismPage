# PrismPage 作り直し仕様

画像重視ビューワーとして PrismPage を作り直すための仕様。製品の振る舞い・確定した設計判断・目標構成・
マイルストーンをここに置く。作業の単位は `TASKS.md`、構造の約束事と危険地帯は `docs/agent-guide/architecture.md`。

## 1. 目標

漫画・画集・スキャン本を「開いてすぐ、迷わず、気持ちよく読める」Windows 向けビューワーにする。
手本は TsubameViewer(フォルダ登録 → サムネイルで辿る → 全画面で読む)。そこに PrismPage 固有の
AI 超解像と、紙の本を思わせる落ち着いた見た目を載せる。

作り直しで解消する現状の問題:

- 読書画面が単一の巨大コンポーネントで、描画方式が二重に動いている。キーボードでページを送れない。
  最終ページで先頭に戻る。進捗が 0% のまま動かない本がある。
- 本をアプリ領域へコピーしてから読む方式で、大量の蔵書に向かない。画像ファイルやフォルダを開けない。
- 画像を base64 で IPC 越しに受け渡しており、重く、メモリが増え続ける。
- 重い処理が同期 command でメインスレッドを塞ぎ、UI が固まる。

## 2. 確定した設計判断

| 項目 | 決定 |
|---|---|
| 技術スタック | Tauri 2 + React + TypeScript を継続。フロントは作り直し、Rust 側は再利用できる部品(EPUB 解析・パス検証・エンジンの導入と実行管理)を分割して残す |
| 本棚の持ち方 | フォルダ登録式(元ファイルはコピーしない)+ 参照のコレクション「本棚」。読みかけ・履歴・お気に入りも持つ |
| 対応形式 | 画像ファイル、画像フォルダ、ZIP/CBZ、画像中心の EPUB、RAR/CBR、PDF。文章中心(リフロー)の EPUB と 7z は対象外 |
| デザイン | C 案「紙の質感」(明朝体の見出し、生成り色の地、朱色のアクセント)。夜間用に同じ書体・構成の暗色テーマ「墨」を用意する |
| AI 超解像 | ビューアの切り替えでその場処理(表示中 → 先読み の優先順)を先に作り、本単位の一括事前処理は後から足す |
| 旧データ | 本棚(取り込み済み EPUB のコピーと localStorage)と設定は引き継がない。AI エンジンの登録簿と導入済みエンジンは引き継ぐ |

デザイン案の比較キャンバス(A/B/C 案のライブラリ画面・ビューア画面)で C 案を選んだ。C 案のライブラリ画面・
ビューア画面の構成(左の文字ナビ、読みかけの一覧、背表紙の本棚、紙色の地に見開き、下端の細い進捗線)を出発点にする。

## 3. 製品仕様

### 3.1 画面と導線

```
左ナビ: 読みかけ(ホーム) / 本棚 / フォルダ / お気に入り / 履歴 / ─ / AI 超解像 / 設定
          │
          ├─ 読みかけ: 続きから読む一覧(表紙・書名・進捗・最終閲覧)
          ├─ 本棚: ユーザーが作るコレクション。背表紙表示と表紙グリッド表示を切り替え
          ├─ フォルダ: 登録フォルダ → サブフォルダ → 本(パンくずで戻る)
          ├─ お気に入り / 履歴
          └─ どこからでも本を選ぶ → ビューア(Esc で元の画面・元のスクロール位置へ戻る)
```

- 本を開く入口: 一覧からの選択、ウィンドウへのドラッグ&ドロップ(ファイル・フォルダ)、「ファイルを開く」、
  ファイル関連付け・コマンドライン引数(2 つ目の起動は既存ウィンドウで開く)。
- 画像ファイルを直接開いたときは、そのファイルがあるフォルダを1冊として、そのページから開く。

### 3.2 本の単位とページ順

- 本 = 画像を直接含むフォルダ / ZIP・CBZ / RAR・CBR / EPUB / PDF。
- ページ順は自然順(`2.jpg` < `10.jpg`)。アーカイブ内のサブフォルダは自然順で平坦化する。画像以外は無視する。
- EPUB は spine 順に各項目の画像をページにする。固定レイアウト(`rendition:layout=pre-paginated`)の
  `page-spread-left/right`・`page-progression-direction` を見開きと綴じ方向に反映する。文章中心の EPUB は
  「文章中心の EPUB には対応していません」と表示して開かない。
- 同じ画像が複数回出てくる本(白紙ページの繰り返しなど)でもページを間引かない。

### 3.3 ビューア

- 表示: 単ページ / 見開き / 自動(ウィンドウが横長なら見開き)。綴じ方向は右綴じ(既定)/ 左綴じ。
  表紙(1 ページ目)単独表示(既定 ON)。横長のページは単独で表示する。見開きの組み合わせを 1 ページずらす操作を持つ。
- 合わせ方: 画面に合わせる(既定)/ 幅に合わせる。背景は紙色(「紙」テーマ)または墨色(「墨」テーマ)。
- 本ごとに表示設定(見開き・綴じ方向・表紙単独)と読書位置を記憶する。
- 先読み: 前後 2 見開き分を事前にデコードしておき、ページ送りで待たせない。
- 本として開いたときは、最終ページで先頭に戻らない。最後の見開きの次に「読み終わりました」の案内を出し、
  次の巻(同じフォルダの自然順で次の本)・最初から読む・閉じるを選べる。案内から前へ送ると最後の見開きに戻る。
- 画像ファイルを直接開いたとき(エクスプローラー・「ファイルを開く」・ドロップで画像を指定し、親フォルダを順に見る)は、
  画像ビューワーと同じく最後の次は最初、最初の前は最後へ回り、「読み終わりました」の案内は出さない。
- ビューアは全画面で開き(Tauri のウィンドウを全画面にする。設定「ビューアを全画面で開く」、既定はオン)、閉じると元のウィンドウの状態に戻す。
  ライブラリはウィンドウのまま。ウィンドウのタイトルバーは Windows 標準のまま。
- 情報バー(上端に戻る・書名・ページ・表示切り替え・AI、下端中央にページ移動のスライダー)は、中央クリックで出し入れする。
  マウスを動かしただけでは出さず、ポインタを画面の上端・下端の帯に入れたときだけ出す(帯から出て操作が止まると隠れる)。
  クリック・ホイール・キー・スワイプでのページ送りでは出さない。帯の高さは 64px(`UI_EDGE_BAND_PX`)で、帯と情報バーの上に
  ポインタがある間は隠さず、帯から出て 2.5 秒操作が無いと隠す。中央クリックで出したバーは、もう一度の中央クリックか
  ページ送りまで出したままにする。拡大中はどこをクリックしても出し入れする。
- スライダーはつまみ付きで、両端に現在のページと総ページを出し、ドラッグ中は行き先のページ番号を出して離した所へ移る。
  右綴じは右から左へ進む。情報バーが隠れている間は下端に細い進捗線だけを出す(表示のみ)。

操作(既定。設定で変えられるのはホイール方向とクリック領域):

| 操作 | 動作 |
|---|---|
| ← / → | 綴じ方向に合わせて次・前(右綴じなら ← が次) |
| Space / Shift+Space、PageDown / PageUp | 次 / 前 |
| Home / End | 最初 / 最後 |
| T / B / Q | 見開き切り替え / 綴じ方向切り替え / 組み合わせを 1 ページずらす |
| F・F11 / Esc | 全画面とウィンドウの切り替え / ビューアを閉じる(全画面なら元のウィンドウに戻して閉じる) |
| クリック | 画面の左右で次・前(綴じ方向に合わせる)。中央で UI の表示切り替え |
| ホイール | 次・前(方向反転は設定) |
| Ctrl+ホイール・中央のダブルクリック・+/- | 拡大縮小。拡大中はドラッグで移動、0 で元に戻す。左右の領域のダブルクリックは 2 回のページ送りのまま(クリックでのページ送りを遅らせない) |
| スワイプ | 次・前 |

### 3.4 ライブラリ

- 登録フォルダは中身をその場で読む(全件の事前スキャンはしない)。表紙サムネイルは初回表示時に生成してキャッシュする。
- 並び替え: 名前 / 更新日 / 最近読んだ。絞り込み: 未読 / 読みかけ / 読了。
- 検索: 表示中のフォルダ内と、登録フォルダ全体(バックグラウンドで作る索引)を対象に、書名・パスを大文字小文字と
  全角半角の違いを無視して部分一致で探す。
- 本棚は参照のコレクション。1 冊を複数の本棚に入れられる。元ファイルが移動・削除されたら「見つかりません」と表示し、
  本棚からは消さない(ユーザーが外す)。

### 3.5 AI 超解像

- 対応エンジンは現行どおり Real-CUGAN / waifu2x / Real-ESRGAN(ncnn-vulkan 版)。導入(公式配布の取得・ZIP 取り込み・
  フォルダ登録・候補検索)、状態確認、登録解除を設定画面で行う。
- ビューアの AI ボタンで本ごとに ON/OFF。ボタンは「AI オン」「AI オフ」と状態を文字で示し、オンのときは朱の地にする。
  ON のとき表示中のページを最優先で処理し、次の数ページを先回りで処理する。
  処理が終わったページから差し替え、処理状況(「AI 2× 適用中」「先の 4 ページを準備中 2/4」)を表示する。
- 本ごとの ON/OFF は、利用者が切り替えた本だけ記録する。記録の無い本(初めて開く本)は、設定の
  「初めて開く本でも AI をオンにする」(既定はオフ)に従う。
- エンジン・モデル・倍率ごとに選べる値だけを見せる(エンジンが対応しない倍率を選ばせない)。
- キャッシュはキーにエンジン・モデル・倍率・ノイズ除去を含める。容量の上限と消去ボタンを持つ。
- 一括事前処理: 本のメニューから全ページを裏で処理する。進捗表示・中止・再開ができる。

### 3.6 設定

表示(テーマ「紙」「墨」「システムに合わせる」、既定の見開き・綴じ方向・表紙単独、ビューアを全画面で開く)/ 操作(ホイール方向、クリック領域)/
ライブラリ(登録フォルダの追加・削除)/ AI 超解像 / アプリ情報と更新確認 / 旧バージョンのデータの削除(明示操作のときだけ消す)。

## 4. 目標構成

### 4.1 Rust(`src-tauri/src/`)

```
lib.rs                 Builder・プラグイン・URI スキーム登録・generate_handler!・起動引数
commands/              公開層(引数検証 → service → AppError)。重い処理はすべて async
  books.rs library.rs viewer.rs engines.rs settings.rs
services/
  source/              ページソースの抽象と実装
    mod.rs             trait PageSource(ページ一覧・ページのバイト列・ページ寸法)、自然順、画像判定
    folder.rs zip.rs rar.rs epub.rs pdf.rs
  store/               SQLite(rusqlite)。スキーマの version と移行
  library/             登録フォルダの走査・分類・検索索引
  thumbs/              サムネイル生成とキャッシュ
  engines/             registry(登録簿)/ installer(取得・展開)/ runner(子プロセス)/ cache / queue(優先度付き)
protocol.rs            prism URI スキーム(ページ・サムネイル・超解像結果の配信)
error.rs               AppError { code, message }(フロントが種類で分岐できる)
models.rs state.rs
```

- 画像の受け渡しはカスタム URI スキーム(`prism`)。ページは `<book-id>/<index>`、サムネイルは `<item-id>`、
  超解像結果はバリアント指定で返す。任意のパスは受け取らない(開いた本の ID と番号だけ)。
- 開いた本はハンドルとしてキャッシュし、アーカイブを開き直さない。RAR(solid 圧縮)は開いた時点で一時領域へ展開し、
  閉じたら片付ける。PDF は要求された大きさで画像化してキャッシュする(PDFium の DLL を同梱)。
  PDF のページ寸法は長い辺を 2048px に合わせた値で返し(見開きの計算はこの縦横比で行う)、指定の無い要求はその大きさで、
  `<book-id>/<index>/width/<px>` の要求はその幅(16〜8192px に丸め、1600 万画素を超えるときは縦横比を保って縮める)で
  PNG にする。画像化は 1 度に 1 枚で、結果は 1 冊あたり 8 枚・合計 64MB まで覚える。
- 1 エントリの読み込みサイズ、展開後の合計サイズ、エントリ数に上限を設ける。
- CSP を有効にする(`default-src 'self'`、画像は `self` と `prism` スキームだけ)。

### 4.2 フロント(`src/`)

```
app/            ルート(読みかけ / 本棚 / フォルダ / お気に入り / 履歴 / 設定 / ビューア)とシェル
design/         トークン(紙・墨)、書体、基本部品(Button・IconButton・TextField・Badge・ProgressLine・Dialog・Toast)
features/
  library/      一覧画面・本棚・検索
  viewer/       ビューア(見開き計算・入力・先読み・拡大)。見開き計算は純粋関数で単体テスト
  ai/           AI 状態表示・エンジン管理画面
  settings/
lib/tauri.ts    command ラッパー(invoke はここだけ)。ブラウザ確認用のモック実装を差し替えで持つ
types/
```

- スタイルは CSS 変数のトークン + CSS Modules。Tailwind・epub.js・clsx・tailwind-merge は外す。
- 書体は Shippori Mincho(見出し)と Zen Kaku Gothic New(本文)を `@fontsource` で同梱する(オフラインで表示が崩れない)。
- 状態は Zustand。永続化は設定だけ(`prismpage-settings` を version 2 にし、旧形式は既定値に置き換える)。
  本・読書状態・本棚は Rust 側の SQLite が持つ。

### 4.3 検証の基盤

- Rust: `cargo test`(ソースの読み出し・パス検証・自然順・スキーマ移行・キャッシュキー)。
- フロント: Vitest(見開き計算・入力の割り当てなど純粋ロジック)。
- 画面確認: `tauri.ts` のモック実装でブラウザだけで全画面を表示し、Playwright で各画面のスクリーンショットを撮る
  (`run shots`、出力は `.harness/shots/`)。UI を変えたタスクは撮ったスクリーンショットを開いて確認する。
- CI に `cargo test` と Vitest を加える。

## 5. マイルストーンと区切り

| # | 内容 | 区切りで確認すること |

- 危険地帯(`architecture.md`)に触れるタスクは探索期でも評価者を通す: URI スキームと CSP、アーカイブ・EPUB のパス、
  外部バイナリ実行、起動引数、フロントと Rust の契約、永続化の形式。
- ユーザーの実機確認(MS3・MS4 の区切り)は反復の外で行う。気になった点は `STEER.md` か次の M1 で反映する。

| RAR の読み出しライブラリ(unrar のソース由来)のライセンスが MIT の本体と合うか | **確認済み: 両立する。** `unrar` クレート(0.5.8)の包み部分は MIT/Apache-2.0。同梱してビルドする UnRAR のソースは RARLAB の freeware ライセンスで、「RAR を扱うためならどのソフトにも無償・無制限で使ってよい(RAR 互換の圧縮ソフトの開発と圧縮方式の再現には使えない)」「他のソフトの中に入れて配ってよい」と定め、組み込んだソフトのライセンスに条件を課さない(コピーレフトではない)。本体は MIT のまま、UnRAR の部分だけがこのライセンスに従う。PrismPage は展開しかしないので禁止事項に当たらない。条件: 配布物(インストーラ・README の第三者ライセンス欄)に UnRAR のライセンス全文を添える(改変した UnRAR のソースを配る場合は「UnRAR source code」で始まる段落を含める — クレートは UnRAR に小さなパッチを当てている)。配布物は OSI 準拠のオープンソースだけでは構成されなくなる点は README に書く。添付は P-02(README と配布設定)で行う |
| RAR のテスト用ファイルを自前で作れない(作成ツールがプロプライエタリ) | テストは RAR 4 形式の無圧縮アーカイブをテストの中で組み立てて UnRAR に読ませる(圧縮・solid・RAR 5 形式は作れない)。圧縮された実ファイル(RAR 5・solid を含む)での確認はユーザーに依頼する |
